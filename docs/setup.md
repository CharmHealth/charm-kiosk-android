# Setup — Build, Run, Test, Release

End-to-end commands and checks for a new developer to clone, build, run, test, and release the app.

## 1. Prerequisites

| Requirement | Version / Notes |
|---|---|
| Android Studio | Meerkat Feature Drop or later (required by AGP 8.10; older releases such as Iguana cannot open the project) |
| JDK | 17 or higher |
| Kotlin | 2.2.20 (matches the CharmAuth SDK) |
| Android Gradle Plugin (AGP) | 8.10.0 |
| Gradle | 8.11.1 |
| CharmHealth account | A kiosk user in CHIS (Auth0) to sign in with |

## 2. Configuration files

| File | Location | How you get it | Purpose |
|---|---|---|---|
| `google-services.json` | `app/` | Download from Firebase using the `charmhealthapps@gmail.com` account (gitignored) | Firebase / Google Services |
| `apptics-config.json` | `app/` | Download per project from **Apptics > Settings > Application IDs** | Zoho Apptics analytics & crash tracking |
| `secure.properties` | project root | Copy `secure.properties.example` and fill in the environment's values (gitignored) | Sign-in configuration (CharmAuth) |

### Firebase configuration

`google-services.json` is **not** in the repo. Sign in to the Firebase console with the `charmhealthapps@gmail.com` account, open this project, and download the file into `app/`. The first build will fail without it.

### Apptics configuration

`apptics-config.json` is downloaded per project from the Apptics console at **Settings > Application IDs**. Place the downloaded file at `app/apptics-config.json`. Do not hand-edit it — any manual change will break analytics.

`local.properties` (project root) is handled automatically — auto-generated by Android Studio on first open, or by Gradle when `ANDROID_HOME` is set. Gitignored.

> Do not modify `google-services.json` or `apptics-config.json` by hand — both are managed by their respective consoles and any automated change will break auth or analytics.

## 3. Clone & build

Replace `<your_repo_username>` with your Zoho repository username:

```bash
git clone --recurse-submodules https://<your_repo_username>@zrepository.zoho.com/medicalmine/charm/Mobile_Team/kiosk-india-android.git
cd kiosk-india-android
./gradlew build
```

The CharmAuth SDK is a git submodule at `native/charm-mobile-auth-sdk`, built with the app
(`includeBuild` in `settings.gradle`). In an existing clone run `git submodule update --init`.
To build against another checkout of the SDK, pass `-PcharmAuthSdkDir=<path>`. The SDK and the
app must use the same Android Gradle Plugin version (Gradle refuses two in one build).

## 4. Run on a device

Target devices are **large and extra-large tablets only**. Phones and small tablets are unsupported — the UI is built exclusively for portrait and landscape tablet layouts and will render incorrectly on phone-sized screens.

```bash
./gradlew installDebug
```

## 5. Test

```bash
# Unit tests
./gradlew test

# Instrumented tests (requires connected device or emulator)
./gradlew connectedDebugAndroidTest

# Full build + all tests
./gradlew clean build
```

Current coverage:

- Unit (`app/src/test/`): `DateUtilTest`, `DateUtilValidateAndFormatTest`, `ModelUtilTest`, `AgeStringFromDateTimeTest`
- Instrumented (`app/src/androidTest/`): `FileUtilTest`

## 6. Release build

### Build variants

| Variant | Debuggable | Minification | ABIs | Version suffix |
|---|---|---|---|---|
| Debug | Yes | Disabled | arm64-v8a, x86_64 | `-DEBUG` |
| Release | No | `minifyEnabled true`, but no-op (see ProGuard below) | armeabi-v7a, arm64-v8a, x86, x86_64 | — |

### ProGuard

Release builds use a deliberately permissive ProGuard config (rules in `app/proguard-rules.pro`):

- Code shrinking disabled (`-dontshrink`)
- Obfuscation disabled (`-dontobfuscate`)
- Optimizations disabled (`-dontoptimize`)
- Source file names preserved for crash debugging

These flags are intentional. Do not enable shrinking, obfuscation, or optimization without explicit team agreement.

### SDK levels

| Field | Value |
|---|---|
| minSdk | 24 |
| targetSdk / compileSdk | 36 |

`versionName` and `versionCode` are not pinned here — they change every release. Check `app/build.gradle.kts` for the current values.

## 7. Sign-in (CharmAuth SDK)

Staff sign in through CHIS and Auth0 with the CharmAuth SDK
([charm-mobile-auth-sdk](https://github.com/CharmHealth/charm-mobile-auth-sdk), submodule
`native/charm-mobile-auth-sdk`), the same as the iOS kiosk.

- **Configuration** — `secure.properties` (`charmAuth.*`, see `secure.properties.example`), per
  environment: Auth0 issuer, the Auth0 Native app's client id (shared with the iOS kiosk), the EHR
  API audience, CHIS's sign-in page, the kiosk's scopes, the EHR base URL, and `apiOrigins` — the
  only origins the access token is sent to (must include the EHR base URL's origin).
- **Redirect** — `com.charmhealth.kiosk:/oauth2/callback`, registered in the Auth0 app's allowed
  callbacks. The SDK's `CharmRedirectActivity` receives it (`manifestPlaceholders["charmAuthRedirectScheme"]`).
- **Code** — `di/AppModule.kt` builds the one `CharmAuthClient` and adds `CharmAuthInterceptor` to
  the EHR OkHttp client (token added, refreshed once on a 401). `common/AuthManager.kt` restores the
  sign-in at startup, signs in (Custom Tab) and out, and maps errors:
  - session ended / not signed in / access denied (any API call, the SDK's `SignedOut(sessionEnded)`
    state, or EHR code 14) → sign out **once**, one "Session expired" alert, login screen;
  - `AuthorizationDenied` `access_denied` / `unauthorized` → "Can't sign in with this account" +
    "Sign in as another user"; other codes → "Sign in failed" + Retry;
  - sign-in timed out → "Sign in timed out" + Retry; network / server busy → "Can't reach the server" + Retry;
  - cancelled, or a sign-in already open → nothing.
- The SDK keeps its sign-in encrypted in `noBackupFilesDir` (Keystore key): logout must not delete it
  by hand — `signOut()` does.
